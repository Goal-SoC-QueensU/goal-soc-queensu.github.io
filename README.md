## 3. Local setup

Node.js 18 or above and pnpm 9 are required. The project uses pnpm, and `pnpm-lock.yaml` is the lock file used during the build.

```bash
git clone https://github.com/Goal-SoC-QueensU/goal-soc-queensu.github.io.git
cd goal-soc-queensu.github.io
pnpm install
pnpm dev
```

| Command | Purpose |
|---|---|
| `pnpm dev` | Development server at http://localhost:3000 |
| `pnpm build` | Static export to the `out` folder, same as the build server |
| `pnpm lint` | ESLint check |
| `npx tsc --noEmit` | TypeScript check |

The build is configured to ignore ESLint and TypeScript errors, so a successful build does not indicate that the code is free of them. The last two commands should therefore be run separately.

## 4. Deployment

Every push to `main` runs the workflow `.github/workflows/gh-pages.yml`, which installs the dependencies, runs `pnpm build`, and publishes the generated `out` folder to the `gh-pages` branch. GitHub Pages serves this branch. Publishing takes about one to three minutes, and the progress can be seen in the Actions tab. Pull requests are built but not published.

In Settings > Pages, the source must remain "Deploy from a branch", with branch `gh-pages` and folder `(root)`.

If a build fails, the version published earlier continues to be served, and the change does not appear on the site. The Actions tab should therefore be checked whenever an update is not visible. A build that succeeds locally may fail on GitHub if a dependency was added without committing the updated `pnpm-lock.yaml`.

## 5. Updating content

The content of the site is stored in JSON files inside the `data` folder. Each page imports the required file and passes it to the component that displays it. For routine updates, only these files need to be edited.

| To update | Edit | Shown on |
|---|---|---|
| News, awards, achievements | `data/news.json` | Home and News |
| Seminars and other events | `data/events.json` | Home |
| Members and alumni | `data/people.json` | People |
| Papers | `data/publications.json` | Publications |
| Projects | `data/research.json` | Research |

Points applicable to all these files:

* Images are kept in `public/images`, and only the file name is written in the JSON, for example `"asif.jpg"`. A path such as `"/images/asif.jpg"` will not work. File names are case sensitive on the build server, so names in lower case may be used.
* Dates are written as `"YYYY-MM-DD"`.
* For an optional link, an empty value `""` hides the link. A value of `"#"` is treated as a valid link and produces a button that leads nowhere. The entry of Dr. Choudhury in `people.json` presently has `"github": "#"`, which may be corrected.
* Items appear in the order in which they are written in the file, except on the News page, which arranges them by date, and the Publications page, which groups them by year.
* An invalid JSON file will fail the build.

### 5.1 News

```json
{
  "title": "Paper accepted at NeurIPS 2026",
  "date": "2026-01-15",
  "excerpt": "One or two sentences, shown on the card.",
  "description": "The complete text, shown when Read More is clicked.\n\nParagraph breaks are preserved.",
  "featured": true,
  "thumbnail": "n004.jpg"
}
```

`title`, `date`, `excerpt` and `description` are required. `featured: false` removes the item from the home page but retains it on the News page. `thumbnail` is optional and appears only in the dialog, not on the card.

New entries should be added at the top of the file, as the home page follows the order of the file. Every entry that is not marked `"featured": false` is shown there, without any limit on the number, so older entries may be marked accordingly.

### 5.2 Events

```json
{
  "title": "GOAL Lab Seminar: Quantum Machine Learning",
  "date": "2026-02-15",
  "location": "Robert Sutherland Hall, Room 503",
  "link": "https://example.com/seminar"
}
```

These are shown on the home page only, and `link` is optional. Events that are over are not removed automatically and have to be deleted from the file. The date is read as UTC, so it may appear one day earlier than intended.

### 5.3 People

```json
{
  "name": "Asif Newaz",
  "position": "PhD Student",
  "role": "PhD Student",
  "photo": "asif.jpg",
  "currentAffiliation": "School of Computing, Queen's University",
  "researchInterests": ["Optimization", "Machine Learning"],
  "bio": "Two or three sentences.",
  "website": "",
  "linkedin": "",
  "github": "",
  "scholar": "",
  "publications": []
}
```

`role` decides the group in which the person appears, and it must be written exactly as one of `Director`, `Researcher`, `PhD Student`, `MSc Student`, `Undergraduate` or `Alumni`. Any other spelling removes the person from the page without showing an error. `position` is free text and is displayed below the name.

| Field | Remarks |
|---|---|
| `photo` | Should always be given, as the fallback image does not exist. A square photograph is suitable |
| `currentAffiliation` | Shown on the card |
| `currentPosition` | Optional, mainly for alumni. It is shown before the affiliation |
| `pastAffiliation` | For alumni. It adds a "Past" line in the dialog |
| `bio`, `researchInterests` | Shown in the dialog |
| `website`, `linkedin`, `github`, `scholar` | A button is shown only if the value is not empty |
| `publications` | Not displayed anywhere, and may be left as `[]` |

When a member leaves the lab, the entry need not be deleted. The `role` may be changed to `Alumni`, `currentPosition` and `currentAffiliation` set to the present place of work, and `pastAffiliation` set to the earlier role in the lab.

### 5.4 Publications

```json
{
  "title": "Paper Title",
  "authors": ["Asif Newaz", "Salimur Choudhury"],
  "venue": "The 50th IEEE Conference on Local Computer Networks (LCN)",
  "year": 2026,
  "link": "https://doi.org/10.1109/...",
  "abstract": "Complete abstract.",
  "thumbnail": "",
  "tags": ["LLM", "Networks"]
}
```

The latest year is shown first, and the position in the file decides the order within a year. The values in `tags` form the topic filters, so the same spelling should be used for the same topic. The search box covers the title, venue and author names, but not the abstract.

`link` should always be given, because the PDF button is shown in every case and an empty value produces a button that does not work. `thumbnail` is optional and appears in the Details dialog.

The "Copy BibTeX" button prepares an entry from these fields when it is clicked. It always produces an `@article` entry, even for conference papers, and the `bibtex` field present in the interface is not used. This can be changed only in [components/publications/publications-list.tsx](components/publications/publications-list.tsx).

### 5.5 Research

```json
{
  "title": "Project Title",
  "image": "r003.png",
  "shortDesc": "Summary shown on the card.",
  "fullDesc": "Detailed description shown in the Learn More dialog.",
  "tags": ["Quantum", "Optimization"]
}
```

`image` is shown on the card as well as in the dialog, and `placeholder-research.png` is used if it is absent. Images in 16:9 proportion are suitable. The values in `tags` form the research area filters.

Some entries also contain `featured` and `relatedPubs`. These are not displayed anywhere, as the featured research section of the home page is commented out in [app/page.tsx](app/page.tsx), and they need not be filled in.

## 6. Notes on the code

* The site is exported statically (`output: "export"`). There is no server, API route, database or form submission, and every page is prepared at build time.
* Details are opened as dialogs and not as separate pages, so an individual news item or paper does not have its own link.
* The dark theme is fixed. The class `dark` is applied in `app/layout.tsx`, and the colours are defined in `app/globals.css`.
* Image paths are formed as `` `${prefix}/images/<file>` ``, where `prefix` comes from `NEXT_PUBLIC_BASE_PATH`. It is empty at present, as the site is served from the root address. The same may be used in any new component.
* The files `styles/globals.css`, `components/theme-provider.tsx` and `components/home/featured-research-section.tsx` are left over from the initial template and are not in use.
